# ASC 트랙 일정 → 구글 캘린더

노션 **'구글 캘린더용 DB'** 페이지를 읽어 **트랙별 구글 캘린더**를 만들고 공개한다.
멤버는 자기 트랙 캘린더 하나만 구독하면 트랙 일정 + 공통 일정을 다 받는다.

사람이 브라우저에서 승인하는 절차가 없어야 **Slack 명령이나 대시보드 버튼으로 한 번에**
돌릴 수 있다. 그래서 사용자 OAuth 가 아니라 **서비스 계정**을 쓴다.

| 파일 | 역할 |
|---|---|
| [`../../gcal_schedule.py`](../../gcal_schedule.py) | 노션 표기 → 이벤트 정규화 + 공통일정 병합 |
| [`../../gcal_sync.py`](../../gcal_sync.py) | 구글 캘린더 생성·동기화. CLI + `sync_all()` |
| [`build_ics.py`](build_ics.py) | `.ics` 생성. 구글 연결 없이 결과 확인용 |

## 쓰는 법

```bash
python3 gcal_sync.py --dry-run                      # 뭐가 바뀌는지만 (자격증명 없어도 됨)
python3 gcal_sync.py --apply --share-with you@gmail.com
python3 gcal_sync.py --links                        # 멤버 배포용 구독 링크
```

`sync_all()` 이 리포트 dict 를 돌려주므로 Slack 메시지로 그대로 옮길 수 있다.

```python
from gcal_sync import sync_all
report = sync_all(dry_run=False, share_with="ops@example.com")
```

## 서비스 계정 준비 (최초 1회)

1. [console.cloud.google.com](https://console.cloud.google.com) → 프로젝트 생성(아무 이름)
2. **API 및 서비스 → 라이브러리 → Google Calendar API → 사용 설정**
3. **사용자 인증 정보 → 서비스 계정 만들기** → 역할 없이 완료
4. 만든 서비스 계정 → **키 → 키 추가 → JSON** → 내려받기
5. 서버 `.env.test` 에 경로를 넣는다

```bash
GOOGLE_SERVICE_ACCOUNT_JSON=/home/ubuntu/asc-gcal-service-account.json
```

JSON 문자열 자체를 넣어도 된다(파일을 못 두는 환경용). 도메인 전체 위임(DWD)은 필요 없다 —
캘린더를 **서비스 계정이 직접 소유**하고, `--share-with` 로 운영자에게 소유권을 넘긴다.

## 동작

- 캘린더 id 는 `gcal_calendars.{ASC_ENV}.json` 에 저장한다(gitignore). 그래서
  `--apply` 를 여러 번 돌려도 캘린더가 새로 생기지 않는다. `GOOGLE_CALENDAR_IDS_JSON`
  환경변수로 덮어쓸 수 있다.
- 일정은 **노션 page id 기준 멱등 upsert**. 노션에서 행을 지우면 캘린더에서도 지워진다.
- **손으로 넣은 일정은 건드리지 않는다.** 이 스크립트가 만든 일정에는
  `syncTag=asc-track-cal` 표식이 붙고, 그 표식이 있는 것만 대상으로 삼는다.
- 새로 만든 캘린더는 **링크를 아는 사람은 누구나 읽기**로 공개된다.

## 표기 해석 규칙

원본이 사람이 읽는 표기라 그대로 캘린더에 못 넣는다.

**연도** — `날짜`에 연도가 없다. 괄호 요일이 실제로 맞아떨어지는지로 검산한다. 11기 46건은
**2026년에서만** 요일이 전부 일치했다(2025·2027은 0건). 연도는 `--year` 또는
`GCAL_SCHEDULE_YEAR` 로 지정하고, 안 주면 올해로 본다.

**시간** — 오전/오후를 **끝쪽에만** 적는 게 이 DB 의 관행이라 앞쪽이 뒤쪽 표기를 물려받는다.
13 이상이면 이미 24시간 표기로 본다.

| 원본 | 해석 |
|---|---|
| `8:00-10:00PM` | 20:00 – 22:00 |
| `10:00-11:00PM` | 22:00 – 23:00 |
| `10:00-13:00AM` | 10:00 – 13:00 (끝이 13 이라 24시간 표기) |
| `7:00~10:00PM` | 19:00 – 22:00 (`~` 도 구분자) |

해석 못 하는 표기가 나오면 **예외를 던지고 멈춘다.** 조용히 건너뛰지 않는다 —
일정 하나가 소리 없이 빠지는 게 더 나쁘다.

**공통 일정 병합** — 오리엔테이션(9/6)은 트랙 DB 와 공통 DB **양쪽에** 적혀 있어 그대로
합치면 두 번 뜬다. **시작·종료가 똑같을 때만** 같은 일정으로 보고 공통 쪽을 버린다.
시간이 겹친다고 버리면 안 된다 — 9/30 외부연사특강(19–21시)과 빌더 4주차 강의(20–22시)처럼
겹치기만 하는 별개 일정이 실제로 있다.
